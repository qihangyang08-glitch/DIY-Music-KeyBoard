# 逐键阈值校准页设计

> 2026-11-13 定稿。状态：**A2 切片 1–4 全部实现**（纯逻辑 + CAL/T 协议 +
> 固件校准流/写阈值 + 校准页面/多指验证 + `calibration.json` 自动下发/
> 重连）。目标版本：A2 **已完成**。
> 关联：[ROADMAP_NEXT.md](ROADMAP_NEXT.md)、[UI_DESIGN_V3.md](UI_DESIGN_V3.md) §13.1、
> [HANDOFF.md](HANDOFF.md) 新阶段交接。
> 本页只做**触键阈值**，不做力度、不做音频分析、不做鼠标弹琴。

## 1. 要解决的问题

用户实测发现两类问题：

1. **弱指按键识别不到**：小拇指按同一块铜箔时，信号峰值明显低于食指；
   全键统一阈值会把小拇指的按下判成“没按”。
2. **多指齐按丢键**：同时按多个键时，相邻电极的基线/耦合让部分键的
   触摸幅度变小（`baseline - filtered` 的正值下降），统一阈值下出现
   “按了但没识别”。

> **信号方向（2026-11-12 实测修正）**：MPR121 的 `filtered` 在触摸时
> **下降**，铜箔实测约 **-55 counts**；固件打印的 `filtered - baseline`
> 是负值。校准流统一发送 **`clamp(baseline - filtered, 0, 255)`**，
> 即“数值越大＝按得越深”，阈值 0–255 的语义才成立。

MPR121 本身支持**每个电极独立的 touch/release 阈值**（寄存器 0x41/0x42
起，每电极 2 字节）。所以正确做法不是继续调一个全局阈值，而是：

- 采集每个键**实际按下过程**的信号曲线；
- 让用户按曲线为每个键单独选阈值；
- 把 32 个键的阈值写回三个 MPR121；
- 用多指和弦做一次验证。

## 2. 不做什么

- 不做力度曲线、不做 velocity；固定力度 100 的产品边界不变。
- 不做自动“AI 调参”；自动建议只是起点，最终由用户点曲线确认。
- 不要求按指定键；用户想先按哪个键就按哪个键。
- 不把校准数据当公开内容；只存本机用户配置。
- 不在校准过程中发声、判定跟弹或写入学习进度。

## 4. 操作流程

### 4.1 空闲

- 显示当前方案名、保存时间、增益、已校准/未校准。
- 「开始检测」在 3 个模块都在线时可用；否则提示缺哪个模块。
- 如果已有方案，显示“当前 32 键阈值已应用”，并提供「重新校准」。

### 4.2 采集噪声底（约 1.5 s）

- 进入后先提示“请松手”，采集每个通道的
  `delta = baseline - filtered`（正值＝越按下）。
- 记录每键 `noise_max`、`noise_mean`。
- 如果任一键噪声底 > 15，提示“该键噪声偏高，检查接线/覆膜”，但仍继续。
- 如果采集期间检测到明显按下，自动重来一次，不把按键算进噪声。

### 4.3 实时监控 + 自动建曲线

- 固件以 25 Hz 上报 32 个键的 delta；PC 为每个**第一次越过触发线**的键
  新建一张曲线图。
- 触发线 = `max(noise_max + 8, 10)`，连续 2 帧越过才建图，避免毛刺。
- 同时按多个键：每个键一张独立图，不合并、不互相覆盖。这是解决
  “多指齐按丢键”的关键观察窗。
- 曲线从该键按下前 200 ms 开始记录（环形缓冲），这样能看到上升沿。
- 用户按下并松开后，delta 回落到释放线以下；所有已触发键都回落并保持
  500 ms，**自动停止检测**，曲线冻结。如果只按了一个键，就是“按下 →
  松开 → 自动结束”，与用户描述的流程一致。
- 如果 30 s 内没有任何键触发，保持等待并提示“还没有检测到按键”；
  不自动退出。
- 如果某个键持续高于释放线 > 5 s，标为“可能卡键”，不自动结束，等用户
  点「停止」。
- 单次检测最长 30 s；到时自动停止并保留已有曲线。

### 4.4 选阈值

- 横轴 = 时间，纵轴 = 信号值（`baseline - filtered`，0–255）。
- 在曲线上点选任意位置：读取该点的**纵坐标**作为候选阈值；
  也可以直接拖动水平阈值线。
- 每张图显示：
  - 峰值 `peak`；
  - 稳定段中位数 `hold`（按下后 150–600 ms 的中位值）；
  - 噪声底 `noise`；
  - 当前阈值线、释放阈值线。
- 快捷按钮：
  - 「用峰值 60%」= `round(peak * 0.60)`；
  - 「用稳定段一半」= `round(hold * 0.50)`；
  - 「恢复建议」= 自动建议值（见 §5）。
- 键盘：`Tab` 聚焦曲线，`←/→` 微调阈值 ±1，`Shift+←/→` ±5，
  `Enter` 选中/应用。曲线不能只靠颜色区分，阈值线同时显示数值。

### 4.5 应用与保存

- 「应用到设备」把 32 组 touch/release 写入固件；成功后状态变“已应用”。
- 「保存方案」写本机 `calibration.json`；下次连接/启动自动应用。
- 「再测一次」清空曲线，重新采集噪声底；不覆盖已保存方案，直到再次保存。
- 离开页面自动停止校准流，恢复普通演奏；未保存的曲线提示一次。

### 4.6 多指验证

**已实现（切片 3）**。应用后在同一页点「多指验证」：

- 用户按和弦（2/3/5 个键），页面显示 32 个键的实时通过/未通过点。
- 通过 = delta 超过该键 touch 阈值（✓）；按了但没识别为 ×；
  余量 < 15% 显示 ! 与黄色底。
- 每格同时显示键号与当前信号值；下方图例说明 ✓ / ! / ×。
- 验证期间重新打开 `CAL` 流；再点「结束验证」或离开页面关闭。
- 验证不发声、不判定、不写学习记录；退出即恢复。

## 5. 阈值规则

### 5.1 建议值

```text
suggested_touch = max(noise_max + 8, round(hold * 0.55), 8)
```

- 上限 255（MPR121 8 位触摸阈值）。
- 如果 `suggested_touch > peak * 0.85`，改用 `round(peak * 0.65)`，
  保证峰值有至少 15% 余量。
- 释放阈值 `release = max(1, round(touch * 0.60))`；默认自动，
  高级模式可单独改。释放阈值必须小于 touch。

### 5.2 校验

保存/应用前逐键检查：

| 条件 | 处理 |
|---|---|
| `touch >= noise_max + 5` | 否则拒绝，提示“阈值离噪声太近，会误触” |
| `touch <= peak * 0.90` | 否则拒绝，提示“阈值太高，正常按下可能识别不到” |
| `peak >= 12` | 否则标记“弱键”，建议提高增益或检查接线 |
| `peak > 255` | 标“饱和”，阈值仍按 255 上限，提示降低增益 |
| `noise_max <= 15` | 否则标记“噪声键”，建议检查接地/覆膜 |

界面必须显示具体数字和原因，不只显示红/绿。

### 5.3 弱键与增益

- 如果某键 `peak < 12`，即使 touch=1 也可能不稳定：不自动改全局增益，
  只提示“该键信号弱；可提高模拟增益或检查电极”。
- 增益是全局的（固件 `g` 循环 1.0x–4.0x）；改增益后已有阈值可能失效，
  页面提示“增益已变，建议重新校准”。
- 方案里记录增益值；加载方案时如果当前增益不同，提示但不静默改。

## 6. 固件协议（需要新增）

### 6.1 校准数据流

新增单字符命令：

- `c`：切换校准流。开启后固件回 `CAL ON`，再发 `c` 回 `CAL OFF`。
- 校准流 25 Hz，每帧一行：

```text
CAL <millis> <v1> <v2> ... <v32>
```

- `vN` = 通道 N（1..32，模块顺序）的
  `clamp(baseline - filtered, 0, 255)`（触摸为正值）。
- 模块不在线时对应位置写 `-1`；PC 画灰色“模块离线”，不画假曲线。
- 固件实现：每模块用两次突发读取（24 B 滤波 + 12 B 基线）算 12 个值，
  25 Hz 下每帧 6 次 I2C 事务；模块 3 只发前 8 个通道（25–32）。
- 25 Hz × 约 180 字节 ≈ 4.5 KB/s；115200 baud 下约 40% 占用，
  与现有状态行/心跳可共存。
- `CAL` 行不进入现有 `parse_line` 状态解析；PC 新增
  `parse_calibration_line`，避免把数字当设备状态。

### 6.2 写入每键阈值

新增行命令：

```text
T <channel> <touch> <release> <channel> <touch> <release> ...
```

- **线上按通道寻址**（2026-11-12 修正）：固件没有 `key -> channel` 表，
  只有通道顺序；PC 的 `mapping/keymap.json` 才是键位真源
  （模块 1 反序：布局键 1 = 通道 12）。PC 用 keymap 把 key 换算成
  channel 后再发送，避免在固件里复制一份映射。
- 第一版发 32 组（通道 1–32）；功能键通道 33–36 保持固件默认。
- 固件按 `channel -> module/electrode` 直接写入
  `0x41 + 2*electrode`（touch）与 `0x42 + 2*electrode`（release）。
- 全部成功回 `OK T`；某个键写失败回 `ERR T <key>`，PC 显示失败键。
  语法错误/无参数回 `ERR T 0`；`release >= touch`、通道越界、重复通道
  均拒绝。
- 新增查询命令 `Q`，固件回当前 32 组 `T ...` 表，便于重连后核对。
- 固件维护 36 通道阈值镜像；`m`/健康检查重新初始化模块后自动重放镜像，
  不会静默丢掉本次会话的逐键校准（NVS 跨重启仍属 C4）。
- 现有单字符命令 `s/m/d/r/x/t/g/h` 保留；`T/Q` 按“读到行尾”解析，
  与单字符命令不冲突。
- MPR121 驱动新增：

```cpp
bool setElectrodeThreshold(TwoWire &wire, uint8_t addr, uint8_t electrode,
                           uint8_t touch, uint8_t release);
```

- **持久化边界**：第一版由 PC 保存并每次连接后重发；固件 NVS 保存
  放到 C4，不在本切片承诺。拔掉 PC 单独上电时仍是固件默认阈值。

### 6.3 连接时序（已实现）

1. 串口连接，3 个模块心跳在线。
2. PC 读取 `calibration.json`；有完整方案则发送 `T ...`。
3. 收到 `OK T` 后状态改为“已应用”；3 s 无应答显示“方案未应用”；
   `ERR T` 显示失败通道；坏文件不发送、不覆盖、只提示一次。
4. 进入校准页时才发送 `c` 开启数据流；离开页面发送 `c` 关闭。
5. 普通演奏期间**不**开启校准流，避免占用串口和刷新 UI。
6. 每次重连都重新读取并下发（固件 RAM 掉电即丢）。

  - `_tick` 仍喂引擎，所以光条显示按下，但不发 `events`；
  - `press_keyboard`/`press_pad` 直接忽略，跟弹/学习/录音不接收事件；
  - 映射、八度、移调、程序、静音、延音全部锁定；
  - 离开页面或关闭窗口必须 `end_calibration()` + 发 `c` 关闭流。

## 8. 数据文件

路径：`%LOCALAPPDATA%\KeyBorad\calibration.json`（与 `learning.json` 同级）。

```json
{
  "version": 1,
  "name": "裸铜 · 桌面 A",
  "created_at": "2026-11-12T20:15:00",
  "gain": 4,
  "keys": [
    {
      "key": 3,
      "channel": 3,
      "note": "D#4",
      "module": "0x5A",
      "electrode": 2,
      "noise": 2,
      "peak": 78,
      "hold": 71,
      "touch": 48,
      "release": 29
    }
  ]
}
```

- `keys` 必须覆盖 1–32；缺键视为未校准，不应用半套方案。
- `version` 不匹配时只读展示，不自动覆盖。
- 第一版单方案；结构预留未来 `profiles` 列表，不在本切片实现多方案 UI。

  - 校准期间不产生 note 事件。
- 回归：普通演奏、跟弹、录音、设备页不受影响；全套测试通过。

### 9.2 人工验收

1. 3 个模块在线，开始检测，松手 1.5 s。
2. 分别用食指、小拇指按同一个弱键，各测一轮；两轮都能建曲线。
3. 同时按 5 个键，5 张曲线都出现，没有合并/丢键。
4. 给弱键选较低阈值，给强键选较高阈值；应用后重连仍生效。
5. 多指验证：5 键全部通过；静置 30 s 无误触。
6. 退出校准页后正常弹奏有声音，跟弹判定正常。
7. 重启应用，方案自动重新应用到设备。

## 10. 风险与后续

- **基线漂移**：MPR121 自动基线会随温度/覆膜变化；方案记录采集时增益，
  漂移明显时提示重测。自适应基线放 C2。
- **阈值上限 255**：信号饱和时不能继续提高阈值；页面提示降增益。
- **模块掉线**：对应键画灰、不写阈值；重新上线后需要重测该模块。
- **固件持久化**：本切片由 PC 重发；NVS 保存放 C4。
- **串口占用**：普通演奏不开校准流；校准页离开立即关闭。
- **未来多方案**：不同覆膜/桌面可保存多套，当前只做单方案。
